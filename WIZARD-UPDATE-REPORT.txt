PAYMENT / FINAL STEP
- Existing Supabase wizard-checkout and wizard-order-status Edge Functions were reviewed.
- wizard-checkout already calculates service pricing server-side, validates selected upsells against platform_upsells, creates an order/tracking number, and creates a Stripe PaymentIntent.
- The current uploaded step-7.js is NOT connected to that production function; it intentionally displays a backend-not-enabled message.
- The current uploaded step-8.js only displays basic payment verification and links to wizard-success.html. It does not yet render the requested branded receipt/POA print documents.
- I did not fake a payment success path. Production checkout/receipt/account creation should be wired against verified Stripe payment status, not a browser-generated paid flag.

SECURITY FINDINGS
- wizard_abandoned_leads currently has legacy broad public INSERT/UPDATE RLS policies. The new save-progress Edge Function makes those broad browser policies unnecessary; they should be tightened after confirming no other production page depends on direct writes.
- wizard-access-gate.js contains a browser-safe anon key; this is acceptable only with correct RLS/Edge Function authorization and is not a service-role secret.
- stripe-paid-signup contains legacy code that should not be used as the source of truth for this wizard checkout. wizard-checkout is materially safer because it retrieves prices server-side.
